## Docker Deployment Scripts

### 🚀 docker-deploy.sh - Complete Interactive Deployment

**The main deployment script** - similar to `k8s/deploy-all.sh` but for Docker.

```bash
./scripts/docker-deploy.sh
```

**Features:**
- 🎨 Clean, colorful terminal output
- ℹ️  Interactive guided setup
- 🔧 Development or production mode selection
- 🔒 Automatic secure password generation
- 💾 Configuration backup and restore
- 🧹 Optional clean start
- ✅ Automated health checks
- 📊 Post-deployment summary with access URLs

<Aside type="tip">
  Perfect for: First-time setup, switching environments, or complete redeployment.
</Aside>

---

### 💻 docker-dev.sh - Quick Development Start

Fast development environment startup with hot-reload enabled.

```bash
./scripts/docker-dev.sh
```

**What it does:**

<Steps>

1. ✅ Checks prerequisites (Docker, Docker Compose)
2. 📝 Creates .env if missing (with dev defaults)
3. 📁 Creates data directories
4. 🚀 Starts development services with hot-reload
5. 📺 Shows live logs

</Steps>

**Development features:**
- Source code mounted as volumes
- Auto-reload on code changes
- Debug builds
- Fast iteration cycle

<Aside>
  Perfect for: Daily development work, quick testing.
</Aside>

---

### 🏭 docker-prod.sh - Production Build & Test

Build and test production-optimized Docker images locally before deployment.

```bash
./scripts/docker-prod.sh
```

**What it does:**

<Steps>

1. ✅ Validates environment configuration
2. 🏗️  Builds optimized production images
3. 📊 Shows image sizes
4. 🧪 Optionally starts services for testing
5. ✅ Runs health checks
6. 📱 Extracts mobile APK (if built)

</Steps>

**Production optimizations:**
- Multi-stage builds
- Minimal base images
- No source volumes
- Release artifacts

<Aside>
  Perfect for: Pre-deployment validation, testing production builds locally.
</Aside>

## GHCR Scripts

### 📦 build-and-push.sh - Push to GitHub Container Registry

Build and push Docker images to GHCR for deployment.

<Tabs>
  <TabItem label="Basic Usage">
    ```bash
    # Push with default 'latest' tag
    ./scripts/build-and-push.sh

    # Push with specific version tag
    ./scripts/build-and-push.sh v1.2.3
    ```
  </TabItem>

  <TabItem label="With Mobile">
    ```bash
    # Include mobile image
    ./scripts/build-and-push.sh v1.2.3 --with-mobile
    ```
  </TabItem>
</Tabs>

**What it does:**

<Steps>

1. 🔐 Checks GHCR authentication
2. 🏗️  Builds production images
3. 🏷️  Tags with specified version
4. ⬆️  Pushes to ghcr.io/assocore/assocore
5. ✅ Confirms success

</Steps>

<Aside>
  Perfect for: Publishing releases, CI/CD pipelines.
</Aside>

---

### 🔑 ghcr-login.sh - GHCR Authentication

Authenticate with GitHub Container Registry.

```bash
./scripts/ghcr-login.sh
```

**What it does:**
- Prompts for GitHub username
- Prompts for GitHub Personal Access Token (PAT)
- Logs into ghcr.io via Docker

**PAT Requirements:**
- Scope: `read:packages` and `write:packages`
- Create at: https://github.com/settings/tokens/new

<Aside>
  Perfect for: Setting up GHCR access, refreshing authentication.
</Aside>

## Common Workflows

### Starting Fresh

<Steps>

1. **Complete clean deployment:**
   ```bash
   ./scripts/docker-deploy.sh
   # Choose "clean start" when prompted
   ```

2. **Or manually:**
   ```bash
   docker compose down -v
   rm -rf data/
   ./scripts/docker-deploy.sh
   ```

</Steps>

### Development Workflow

<Steps>

1. **Day 1: Initial setup**
   ```bash
   ./scripts/docker-deploy.sh
   # Choose "development" mode
   ```

2. **Day 2+: Quick start**
   ```bash
   ./scripts/docker-dev.sh
   # Or: docker compose up
   ```

</Steps>

### Release Workflow

<Steps>

1. **Test production build locally:**
   ```bash
   ./scripts/docker-prod.sh
   ```

2. **If tests pass, push to registry:**
   ```bash
   ./scripts/build-and-push.sh v1.2.3
   ```

3. **Deploy to Kubernetes (if using K8s):**
   ```bash
   ./k8s/deploy-all.sh
   ```

</Steps>

### Switching Environments

<Tabs>
  <TabItem label="Dev → Prod">
    ```bash
    docker compose down
    ./scripts/docker-deploy.sh
    # Choose "production" mode
    ```
  </TabItem>

  <TabItem label="Prod → Dev">
    ```bash
    docker compose --profile prod down
    ./scripts/docker-deploy.sh
    # Choose "development" mode
    ```
  </TabItem>
</Tabs>

## Environment Variables

All scripts respect the `.env` file in `back/.env`:

```bash
# Database
MARIADB_ROOT_PASSWORD=...
NEXTCLOUD_DB_NAME=...
NEXTCLOUD_DB_USER=...
NEXTCLOUD_DB_PASSWORD=...

# Backend
DATABASE_URL=...
ENVIRONMENT=development|production

# Nextcloud
NEXTCLOUD_ADMIN_USER=...
NEXTCLOUD_ADMIN_PASSWORD=...

# Security
JWT_SECRET_KEY=...
```

<Aside type="caution">
  **Location:** `back/.env` (gitignored)  
  **Creation:** Automatically created by scripts or manually from `.env.example`
</Aside>

## Troubleshooting

### Script won't execute

```bash
# Make scripts executable
chmod +x scripts/*.sh

# Or run with bash
bash scripts/docker-deploy.sh
```

### Docker daemon not running

<Tabs>
  <TabItem label="Linux">
    ```bash
    sudo systemctl start docker
    sudo systemctl status docker
    ```
  </TabItem>

  <TabItem label="macOS/Windows">
    Start Docker Desktop application
  </TabItem>
</Tabs>

### Permission errors

```bash
# Add user to docker group (Linux)
sudo usermod -aG docker $USER
newgrp docker

# Or run with sudo (not recommended)
sudo ./scripts/docker-deploy.sh
```

### Port conflicts

```bash
# Check what's using the port
sudo lsof -i :8000

# Kill the process
kill -9 <PID>

# Or change ports in docker-compose.yml
```

### .env file issues

```bash
# Regenerate .env
rm back/.env
./scripts/docker-deploy.sh
# Will create new .env with prompts
```

### Git Hooks

Add to `.git/hooks/pre-push`:

```bash
#!/bin/bash
# Test production build before push
./scripts/docker-prod.sh
```

### CI/CD

GitHub Actions example:

```yaml
- name: Build and Push
  run: |
    echo "${{ secrets.GITHUB_TOKEN }}" | docker login ghcr.io -u ${{ github.actor }} --password-stdin
    ./scripts/build-and-push.sh ${{ github.ref_name }}
```

RED='\033[0;31m'

### Best Practices

When adding new scripts:

<Steps>

1. ✅ Add shebang: `#!/bin/bash`
2. ✅ Set error handling: `set -e`
3. ✅ Add usage comment at top
4. ✅ Use color variables for output
5. ✅ Make executable: `chmod +x`
6. ✅ Document in this reference
7. ✅ Test on clean environment

</Steps>
