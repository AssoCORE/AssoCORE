This guide explains how to securely manage secrets (passwords, credentials, API keys) for AssoCORE deployments.

<Aside type="danger" title="Security First">
**NEVER commit secrets to version control!**

All sensitive credentials must be:
- Stored in `.env` files (excluded from git)
- Managed through Kubernetes secrets
- Rotated regularly
- Generated with strong randomness
</Aside>

---

## Quick Start

### 1. Create Your Secrets Configuration

```bash
# Copy the template
cp k8s/.env.example k8s/.env

# Generate secure passwords
openssl rand -base64 32  # Run this for each password

# Edit the file with your favorite editor
nano k8s/.env
```

### 2. Fill in Required Values

Edit `k8s/.env` and set all values:

```bash
# Database
MARIADB_ROOT_PASSWORD=your-secure-password-here
MARIADB_DATABASE=assocore
MARIADB_USER=assocore
MARIADB_PASSWORD=another-secure-password

# NextCloud
NEXTCLOUD_ADMIN_USER=admin
NEXTCLOUD_ADMIN_PASSWORD=nextcloud-secure-password
```

### 3. Create Kubernetes Secrets

```bash
# Run the secret creation script
./k8s/01-secrets/create-app-secrets.sh
```

This will create three secrets:

- `mariadb-secret` - Database credentials
- `backend-db-secret` - Backend database connection string
- `nextcloud-secret` - NextCloud admin credentials

## What Gets Created

<Tabs>
  <TabItem label="mariadb-secret">
    Contains database credentials used by MariaDB and all applications that connect to it.

    ```yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: mariadb-secret
      namespace: assocore
    type: Opaque
    data:
      root-password: <base64-encoded>
      database: <base64-encoded>
      user: <base64-encoded>
      password: <base64-encoded>
    ```
  </TabItem>
  
  <TabItem label="backend-db-secret">
    Contains the full database connection URL for the FastAPI backend.

    ```yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: backend-db-secret
      namespace: assocore
    type: Opaque
    data:
      database-url: <base64-encoded>
    ```
  </TabItem>
  
  <TabItem label="nextcloud-secret">
    Contains NextCloud admin credentials and database connection info.

    ```yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: nextcloud-secret
      namespace: assocore
    type: Opaque
    data:
      mysql-database: <base64-encoded>
      mysql-user: <base64-encoded>
      mysql-password: <base64-encoded>
      nextcloud-admin-user: <base64-encoded>
      nextcloud-admin-password: <base64-encoded>
    ```
  </TabItem>
</Tabs>

## Managing Secrets

### Viewing Secrets

```bash
# List all secrets
kubectl get secrets -n assocore

# View secret details (base64 encoded)
kubectl get secret mariadb-secret -n assocore -o yaml

# Decode a specific value
kubectl get secret mariadb-secret -n assocore -o jsonpath='{.data.password}' | base64 -d
```

### Updating Secrets

To change a password:

```bash
# 1. Edit your .env file with new values
nano k8s/.env

# 2. Regenerate secrets
./k8s/01-secrets/create-app-secrets.sh

# 3. Restart affected pods to pick up new secrets
kubectl rollout restart statefulset/mariadb -n assocore
kubectl rollout restart deployment/backend -n assocore
kubectl rollout restart statefulset/nextcloud -n assocore
```

### Deleting Secrets

```bash
# Delete a specific secret
kubectl delete secret mariadb-secret -n assocore

# Delete all application secrets
kubectl delete secret mariadb-secret backend-db-secret nextcloud-secret -n assocore
```

## Best Practices

### Password Generation

Always use cryptographically secure random passwords:

<Tabs>
  <TabItem label="OpenSSL">
    ```bash
    # Generate a 32-character password
    openssl rand -base64 32

    # Generate multiple passwords at once
    for i in {1..3}; do 
      echo "Password $i: $(openssl rand -base64 32)"
    done
    ```
  </TabItem>
  
  <TabItem label="pwgen">
    ```bash
    # Install pwgen
    sudo apt install pwgen

    # Generate 5 passwords, 32 characters each
    pwgen -s 32 5
    ```
  </TabItem>
  
  <TabItem label="Python">
    ```python
    import secrets
    import string

    # Generate a secure password
    alphabet = string.ascii_letters + string.digits + string.punctuation
    password = ''.join(secrets.choice(alphabet) for i in range(32))
    print(password)
    ```
  </TabItem>
</Tabs>

### Password Requirements

<CardGrid>
  <Card title="Minimum Length" icon="pencil">
    24 characters minimum for production
  </Card>
  
  <Card title="Complexity" icon="puzzle">
    Mix of letters, numbers, and symbols
  </Card>
  
  <Card title="Uniqueness" icon="star">
    Different password for each service
  </Card>
  
  <Card title="Rotation" icon="refresh">
    Change every 90 days
  </Card>
</CardGrid>

### .env File Security

```bash
# Ensure .env is not readable by others
chmod 600 k8s/.env

# Verify it's in .gitignore
grep "k8s/.env" .gitignore

# Never commit it
git status  # Should not show k8s/.env
```

## Production Recommendations

### External Secret Management

For production environments, use external secret managers:

<Tabs>
  <TabItem label="Sealed Secrets">
    ```bash
    # Install sealed-secrets controller
    kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.24.0/controller.yaml

    # Seal a secret
    kubeseal --format yaml < mysecret.yaml > mysealedsecret.yaml

    # Commit the sealed secret (safe to store in git)
    git add mysealedsecret.yaml
    ```
  </TabItem>
  
  <TabItem label="HashiCorp Vault">
    ```bash
    # Install Vault
    helm install vault hashicorp/vault

    # Configure Kubernetes auth
    vault auth enable kubernetes

    # Create secrets
    vault kv put secret/assocore/db password="secure-password"
    ```
  </TabItem>
  
  <TabItem label="External Secrets Operator">
    Use cloud provider secret managers (AWS/Azure/GCP):

    ```bash
    # Install External Secrets Operator
    helm install external-secrets external-secrets/external-secrets

    # Create SecretStore
    kubectl apply -f - <<EOF
    apiVersion: external-secrets.io/v1beta1
    kind: SecretStore
    metadata:
      name: aws-secrets-manager
      namespace: assocore
    spec:
      provider:
        aws:
          service: SecretsManager
          region: us-east-1
    EOF
    ```
  </TabItem>
</Tabs>

### Secret Rotation Strategy

```bash
# 1. Update .env with new password
# 2. Create new secret (keeps old one)
# 3. Update deployments to use new secret
# 4. Verify all pods are running
# 5. Delete old secret
```

### Audit Secret Access

```bash
# Enable audit logging in Kubernetes
# Check who accessed secrets
kubectl logs -n kube-system kube-apiserver-* | grep "secret"

# Use RBAC to restrict secret access
kubectl create role secret-reader --verb=get --resource=secrets
```

## Troubleshooting

### Secret Not Found

<Aside type="caution">
**Problem:** `kubectl get secret mariadb-secret -n assocore` returns "not found"

**Solution:**
```bash
# Check if secret exists
kubectl get secret mariadb-secret -n assocore

# If missing, recreate it
./k8s/01-secrets/create-app-secrets.sh
```
</Aside>

### Permission Denied

```bash
# Check your RBAC permissions
kubectl auth can-i get secrets -n assocore

# Check ServiceAccount permissions
kubectl get rolebinding -n assocore
```

### Pod Can't Read Secret

```bash
# Check pod events
kubectl describe pod <pod-name> -n assocore

# Verify secret is mounted
kubectl exec -it <pod-name> -n assocore -- ls -la /path/to/secret
```

### Base64 Encoding Issues

```bash
# Properly encode a value
echo -n "my-password" | base64

# Properly decode a value
echo "bXktcGFzc3dvcmQ=" | base64 -d
```

## Emergency Procedures

### Lost .env File

If you lose your `.env` file but secrets exist in Kubernetes:

```bash
# Extract and decode all values
kubectl get secret mariadb-secret -n assocore -o json | \
  jq -r '.data | to_entries[] | "\(.key)=\(.value | @base64d)"' > k8s/.env.recovered
```

### Compromised Credentials

<Aside type="danger" title="Security Incident Response">
If credentials are compromised:

```bash
# 1. Immediately generate new passwords
for i in {1..5}; do openssl rand -base64 32; done

# 2. Update .env with new values
nano k8s/.env

# 3. Recreate all secrets
./k8s/01-secrets/create-app-secrets.sh

# 4. Force restart all pods
kubectl delete pods --all -n assocore

# 5. Verify new credentials work
kubectl logs -f deployment/backend -n assocore
```
</Aside>
