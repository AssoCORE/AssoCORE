## Quick Start Scripts

The `back/` directory includes three interactive scripts:

### 🚀 setup.sh - Complete Setup

First-time setup or clean install with all services.

```bash
cd back
./setup.sh
```

<Steps>

1. **Checks prerequisites**
   - Docker and Docker Compose availability
   - Environment configuration validation
   
2. **Optional Python environment**
   - Prompts to setup local env with uv
   
3. **Clean start option**
   - Shows current data size
   - Option to delete and start fresh
   
4. **Starts all services**
   - MariaDB, Redis, Nextcloud, API
   - **Proper health checks** (no more sleep timers!)
   
5. **Configures Nextcloud**
   - Sets trusted domains
   - Optional app installation (calendar, contacts, notes)
   
6. **Post-deployment summary**
   - Service URLs
   - Quick commands
   - Access information

</Steps>

<Aside type="note">
  **Health Checks Included:**
  - MariaDB: `mariadb-admin ping` (90s timeout)
  - Redis: `redis-cli ping` (30s timeout)
  - Nextcloud: `curl status.php` (120s timeout)
  - API: `curl /health` (60s timeout)
</Aside>

---

### 💻 dev.sh - Development Mode

Quick start for daily development with hot-reload.

```bash
cd back
./dev.sh
```

**Features:**
- 🔥 Hot-reload enabled (code changes apply instantly)
- 📁 Source code mounted as volume
- 🔍 Detailed logging
- ⚡ Smart infrastructure detection (only starts what's needed)

**What it does:**

<Steps>

1. Checks prerequisites
2. Detects running services
3. Starts infrastructure if needed (DB, Redis, Nextcloud)
4. Waits for services with health checks
5. Stops production API if running
6. Starts development API with live logs

</Steps>

---

### 🛑 shutdown.sh - Interactive Shutdown

Stop services with data preservation options.

<Tabs>
  <TabItem label="Interactive">
    ```bash
    cd back
    ./shutdown.sh
    ```
    
    Prompts you to choose:
    1. Stop containers (keep data)
    2. Stop and delete all data
  </TabItem>
  
  <TabItem label="Keep Data">
    ```bash
    ./shutdown.sh --keep-data
    ```
    
    Quick shutdown preserving all data
  </TabItem>
  
  <TabItem label="Clean All">
    ```bash
    ./shutdown.sh --clean
    ```
    
    Stop and delete all data (requires confirmation)
  </TabItem>
  
  <TabItem label="Help">
    ```bash
    ./shutdown.sh --help
    ```
    
    Show usage and options
  </TabItem>
</Tabs>

## Environment Configuration

Configuration is stored in `back/.env` (gitignored).

### Required Variables

```bash
# MariaDB root
MARIADB_ROOT_PASSWORD=your_root_password
MYSQL_ROOT_PASSWORD=your_root_password

# App database
MYSQL_DATABASE=my_app_db
MYSQL_USER=my_app_user
MYSQL_PASSWORD=your_db_password
MYSQL_HOST=db
MYSQL_PORT=3306

# Nextcloud database
NEXTCLOUD_DB_NAME=nextcloud
NEXTCLOUD_DB_USER=nextcloud
NEXTCLOUD_DB_PASSWORD=your_nextcloud_db_password

# Nextcloud API
NEXTCLOUD_URL=http://nextcloud
NEXTCLOUD_USER=admin
NEXTCLOUD_PASSWORD=your_nextcloud_admin_password

# JWT — MUST be changed before any deployment
SECRET_KEY=change-me-to-a-random-secret-in-production

# Optional — overrides the individual MYSQL_* vars
# DATABASE_URL=mysql+aiomysql://user:pass@host:port/db
```

<Aside type="caution">
  **`SECRET_KEY` must be set to a strong random value in production.** All JWTs are signed with this key — if it leaks, any user's session can be forged. Generate one with `python -c "import secrets; print(secrets.token_hex(32))"`.
</Aside>

```
└── docker-compose.dev.yml
```

## Development Workflows

### Typical Development Day

<Steps>

1. **Start development environment**
   ```bash
   cd back
   ./dev.sh
   ```

2. **Make code changes**
   - Edit files in `app/`
   - Hot-reload applies changes automatically
   - View logs in terminal

3. **Test endpoints**
   - Open http://localhost:8000/docs
   - Use Swagger UI to test APIs
   - Check logs for errors

4. **View service logs** (if needed)
   ```bash
   # In another terminal
   docker compose logs -f api-dev
   docker compose logs -f db
   docker compose logs -f nextcloud
   ```

5. **Stop when done**
   ```bash
   # Press Ctrl+C to stop API
   ./shutdown.sh --keep-data
   ```

</Steps>

---

### Fresh Start Workflow

When you need to start completely fresh (clean database, etc.):

<Steps>

1. **Clean everything**
   ```bash
   ./shutdown.sh --clean
   ```

2. **Start fresh setup**
   ```bash
   ./setup.sh
   ```

3. **Complete Nextcloud setup** (if needed)
   - Visit http://localhost:8081
   - Use credentials from `.env`

</Steps>

---

### Adding New Endpoints

<Steps>

1. **Create a route file** in `app/routes/`
   ```bash
   touch app/routes/myfeature.py
   ```

2. **Define a router and handlers**
   ```python
   from fastapi import APIRouter, Depends
   from sqlalchemy.ext.asyncio import AsyncSession
   from app.db.database import get_session
   from app.core.dependencies import get_current_user
   from app.db.models import User

   router = APIRouter(prefix="/myfeature", tags=["myfeature"])

   @router.get("/")
   async def list_items(
       current_user: User = Depends(get_current_user),
       session: AsyncSession = Depends(get_session),
   ):
       return []
   ```

3. **Done — no manual registration needed**

   `routes/__init__.py` auto-discovers every module in the package that exports `router: APIRouter` and mounts it under `/api`. Hot-reload picks up the new file immediately.

4. **Test in Swagger UI**
   - Visit http://localhost:8000/docs

</Steps>

<Aside type="tip">
  Use `Depends(get_current_user)` from `app.core.dependencies` to protect any route. It validates the JWT and returns the current `User` ORM object, or raises 401 automatically.
</Aside>

    ```bash
    docker compose ps
    
    # View all logs
    ```

    ```bash
    ./shutdown.sh --clean
    ./setup.sh
    ```
  </TabItem>

---

### Database Issues

**Database not ready:**
- Scripts include proper health checks
- No more arbitrary sleep timers
- Automatic retry with 90s timeout

**Connection errors:**
```bash
# Check database health
docker compose exec db mariadb-admin ping -h localhost

# Connect to database
docker compose exec db mariadb -u root -p

# Check DATABASE_URL in .env
cat .env | grep DATABASE_URL
```

---

### Nextcloud Issues

**Nextcloud slow to start:**
- First start can take 2-3 minutes
- Health check timeout is 120s
- Check logs: `docker compose logs -f nextcloud`

**Trusted domain errors:**
```bash
# Reconfigure trusted domains
docker compose exec -u www-data nextcloud php occ config:system:set trusted_domains 0 --value=localhost:8081
docker compose exec -u www-data nextcloud php occ config:system:set trusted_domains 1 --value=nextcloud
```

---

### API Issues

**Hot-reload not working:**
```bash
# Ensure using dev.sh or docker-compose.dev.yml
./dev.sh

# Check mounted volumes
docker compose -f docker-compose.yml -f docker-compose.dev.yml config | grep volumes
```

**Import errors:**
```bash
# Rebuild image
docker compose build api-dev

# Check Python environment
docker compose exec api-dev uv pip list
```

## Advanced Usage

### Local Development (No Docker)

For API development without Docker:

<Steps>

1. **Setup Python environment**
   ```bash
   uv sync
   ```

2. **Start external services**
   ```bash
   # Start only infrastructure
   docker compose up -d db redis nextcloud
   ```

3. **Run API locally**
   ```bash
   uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
   ```

</Steps>

<Aside type="note">
  You still need MariaDB, Redis, and Nextcloud running (via Docker or natively).
</Aside>

---

### Custom Docker Image

Build a custom backend image:

```bash
# Build with custom tag
docker build -t assocore-backend:custom .

# Use in docker-compose.yml
# Change `build: .` to `image: assocore-backend:custom`
```

### Database Migrations

<Aside type="caution">
  Alembic migrations are not yet implemented. This is a future enhancement.
</Aside>

If using Alembic in the future:

```bash
# Generate migration
docker compose exec api alembic revision --autogenerate -m "Add users table"

# Apply migrations
docker compose exec api alembic upgrade head

# Rollback
docker compose exec api alembic downgrade -1
```

- Set proper resource limits in docker-compose.yml
