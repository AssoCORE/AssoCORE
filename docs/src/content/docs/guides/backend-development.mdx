## Quick Start

<Steps>

1. **Create the env file** (first time only)

   ```bash
   cp .env.example .env
   ```

2. **Start the stack**

   ```bash
   docker compose up --wait
   ```

   `--wait` blocks until every service reports healthy, so there is no need to poll
   or guess. If a required variable is missing, Compose stops and names it rather
   than starting MariaDB with blank credentials.

3. **Develop**

   The `dev` profile mounts `./back` into the container and runs uvicorn with
   `--reload`, so code changes apply instantly.

4. **Stop**

   ```bash
   docker compose down          # keep data
   docker compose down -v       # also drop volumes
   ```

</Steps>

## Environment Configuration

There is one `.env`, at the repository root, created from the tracked `.env.example`.
Compose uses it for two things at once:

1. resolving the `${VAR}` substitutions inside `docker-compose.yml`, and
2. as the `env_file` injected into the `db`, `nextcloud` and `backend` containers.

The first is why it must sit next to `docker-compose.yml`, and why compose has to be run
from the repository root — Compose looks for `.env` in the directory you invoke it from.
It is gitignored; never commit it.

<Aside type="note">
  This used to be split between a repo-root `.env` and a `back/.env` that had to be kept in sync by hand. They were merged: the drift silently produced blank credentials.
</Aside>

### Key variables

```bash
# MariaDB root
MYSQL_ROOT_PASSWORD=root_password

# App database (the backend's own, separate from Nextcloud's)
MYSQL_USER=my_app_user
MYSQL_PASSWORD=my_app_password
MYSQL_DATABASE=my_app_db
MYSQL_HOST=db
MYSQL_PORT=3306

# Nextcloud database
NEXTCLOUD_DB_NAME=nextcloud
NEXTCLOUD_DB_USER=nextcloud
NEXTCLOUD_DB_PASSWORD=nextcloud_db_password

# Nextcloud API — NEXTCLOUD_URL resolves only inside the docker network,
# NEXTCLOUD_PUBLIC_URL is what a browser can reach
NEXTCLOUD_URL=http://nextcloud
NEXTCLOUD_PUBLIC_URL=http://localhost:8081
NEXTCLOUD_ADMIN_USER=admin
NEXTCLOUD_ADMIN_PASSWORD=admin

# Auth
SECRET_KEY=change-me-in-production
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_DAYS=30
REFRESH_GRACE_SECONDS=10
AUTH_REDIS_STRICT=false

# Bootstrap admin — without ADMIN_PASSWORD no admin is seeded
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ChangeMe132!
ADMIN_EMAIL=admin@assocore.local
```

<Aside type="caution">
  **`SECRET_KEY` must be set to a strong random value before any deployment.** All JWTs are signed with it — if it leaks, any user's session can be forged. Generate one with `openssl rand -hex 32`.

  In production also set `NC_APP_PASSWORD_KEY` to an independent Fernet key; it otherwise derives from `SECRET_KEY`, which means one leak decrypts every stored Nextcloud app password.
</Aside>

<Aside type="note">
  Setting `DATABASE_URL` overrides the individual `MYSQL_*` variables that
  `db/database.py` otherwise composes the connection string from.
</Aside>

## Project Structure

```
back/
├── app/
│   ├── main.py              # FastAPI app — lifespan, CORS, router mount
│   ├── core/
│   │   ├── security.py      # bcrypt + PyJWT helpers
│   │   ├── tokens.py        # redis-backed blacklist + refresh rotation
│   │   └── dependencies.py  # get_current_user, require_roles
│   ├── db/
│   │   ├── database.py      # Async engine, session factory, init_db()
│   │   ├── models.py        # SQLAlchemy ORM models
│   │   └── seed.py          # Default roles + bootstrap admin
│   ├── schemas/
│   │   └── classes.py       # Pydantic request/response schemas
│   └── routes/              # Auto-discovered route modules
│       ├── __init__.py      # pkgutil discovery, mounted at the app root
│       ├── user.py          # Auth, users, notifications, reminders
│       ├── events.py        # Event CRUD (stubs)
│       ├── apps.py          # Nextcloud app proxies (stubs)
│       ├── storage.py       # Nextcloud-backed storage
│       └── nextcloud.py     # Nextcloud admin routes (admin-gated)
├── pyproject.toml           # uv dependencies
└── uv.lock
```

The Dockerfile lives at `docker/backend.Dockerfile` (multi-stage, with `development`
and `production` targets) and is shared by Compose and CI.

| `/user/{id}` | GET/DELETE | required | Get / delete user by ID |
| `/user/notification/` | GET | required | List notifications |
| `/user/notification/{id}` | GET/DELETE | required | Single notification |

| `/user/notification/unread/{id}` | PUT | required | Mark as unread |
| `/user/reminder/` | GET/POST/DELETE | required | Reminders |

## Development Workflows

### Typical Development Day

<Steps>

1. **Start the stack**
   ```bash
   docker compose up --wait
   ```

2. **Make code changes**
   - Edit files in `back/app/`
   - Hot-reload applies changes automatically

3. **Test endpoints**
   - Open http://localhost:8000/docs
   - Use Swagger UI to exercise the API

4. **View logs**
   ```bash
   docker compose logs -f backend
   docker compose logs -f db
   docker compose logs -f nextcloud
   ```

5. **Stop when done**
   ```bash
   docker compose down
   ```

</Steps>

---

### Fresh Start Workflow

When you need a completely clean database:

```bash
docker compose down -v
# the bind-mounted data dirs are owned by the container user
sudo rm -rf data/db data/nextcloud
docker compose up --wait
```

Nextcloud reinstalls itself on first boot from `NEXTCLOUD_ADMIN_USER` /
`NEXTCLOUD_ADMIN_PASSWORD` / `NEXTCLOUD_TRUSTED_DOMAINS`; no manual `occ` step is
needed. Confirm with `curl -s http://localhost:8081/status.php`, which should report
`"installed":true`.

---

### Adding New Endpoints

<Steps>

1. **Create a route file** in `back/app/routes/`
   ```bash
   touch back/app/routes/myfeature.py
   ```

2. **Define a router and handlers**
   ```python
   from fastapi import APIRouter, Depends
   from sqlalchemy.ext.asyncio import AsyncSession
   from app.db.database import get_session
   from app.core.dependencies import get_current_user
   from app.db.models import User

   router = APIRouter(prefix="/myfeature", tags=["myfeature"])

   @router.get("/")
   async def list_items(
       current_user: User = Depends(get_current_user),
       session: AsyncSession = Depends(get_session),
   ):
       return []
   ```

3. **Done — no manual registration needed**

   `routes/__init__.py` auto-discovers every module in the package that exports
   `router: APIRouter` and mounts it at the app root. Hot-reload picks up the new
   file immediately.

4. **Test in Swagger UI** at http://localhost:8000/docs

</Steps>

<Aside type="tip">
  Use `Depends(get_current_user)` from `app.core.dependencies` to protect a route, or `Depends(require_admin)` for admin-only routes — prefer putting the gate in `APIRouter(dependencies=[...])` so new routes in that file cannot forget it.
</Aside>

<Aside type="caution">
  Async SQLAlchemy does not support lazy loading. Always use `selectinload` or `joinedload` when a route needs relationships.
</Aside>

## Troubleshooting

### Services Not Starting

<Tabs>
  <TabItem label="Check Docker">
    ```bash
    docker info
    docker compose ps
    docker compose logs -f
    ```
  </TabItem>

  <TabItem label="Check Config">
    ```bash
    # Resolves every ${VAR}; errors if one is missing
    docker compose config
    ```

    If this prints `required variable ... is missing a value`, your repo-root `.env`
    is absent or incomplete — `cp .env.example .env`.
  </TabItem>

  <TabItem label="Check Ports">
    ```bash
    sudo lsof -i :8000  # API
    sudo lsof -i :8081  # Nextcloud
    sudo lsof -i :3306  # MariaDB
    ```
  </TabItem>
</Tabs>

---

### Database Issues

```bash
# Health, the same way the healthcheck does it
docker compose exec db mariadb-admin ping -h 127.0.0.1 -u root -p"$MYSQL_ROOT_PASSWORD" --silent

# Interactive shell
docker compose exec db mariadb -u root -p
```

<Aside type="caution">
  `mariadb-admin ping -h localhost` (without credentials) connects over the unix socket as a passwordless root and logs `Access denied for user 'root'@'localhost' (using password: NO)` on the server. Use `-h 127.0.0.1` with credentials — the socket path can also report healthy before TCP is actually accepting connections.
</Aside>

**`Access denied ... (using password: NO)` repeating every few seconds** almost always
means a healthcheck or script is pinging without credentials, not that your password
is wrong.

**Credentials look right but auth still fails:** MariaDB only applies
`MARIADB_ROOT_PASSWORD` when it *initialises* an empty data directory. If `./data/db`
already exists from an earlier run, changing `.env` has no effect — remove the
directory and let it reinitialise.

---

### Nextcloud Issues

**Slow to start:** first boot installs the app and can take a couple of minutes.
Watch `docker compose logs -f nextcloud` for `installed`.

**Trusted domain errors:**
```bash
docker compose exec -u www-data nextcloud php occ config:system:set trusted_domains 0 --value=localhost:8081
```

---

### API Issues

**Hot-reload not working:**
```bash
# Confirm ./back is mounted into the dev container
docker compose config | grep -A5 'backend:'
```

**Import errors after adding a dependency:** the image installs dependencies at build
time from `pyproject.toml`/`uv.lock`, so pulling new code is not enough — rebuild:
```bash
docker compose build backend
```

## Advanced Usage

### Local Development (No Docker)

<Steps>

1. **Setup Python environment**
   ```bash
   cd back && uv sync
   ```

2. **Start infrastructure only**
   ```bash
   docker compose up -d db redis nextcloud
   ```

3. **Run the API locally**
   ```bash
   cd back && uv run dev
   ```

</Steps>

<Aside type="note">
  `MYSQL_HOST` in `.env` is `db`, which only resolves inside the docker network. Point it at `127.0.0.1` when running the API on the host.
</Aside>

---

### Database Migrations

<Aside type="caution">
  There is no migration tool. `metadata.create_all` only creates missing **tables** — it never adds a column to an existing one, so adding a field to a live model is a silent no-op against an existing database. Model new data as a new table, or introduce Alembic.
</Aside>

## CI/CD Integration

CI builds images directly from `docker/backend.Dockerfile` — see
`.github/workflows/docker-build.yml`. A test job against the stack looks like:

```yaml
name: Backend Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup environment
        run: |
          cp .env.example .env

      - name: Start services
        run: docker compose up -d --wait

      - name: Run tests
        run: docker compose exec -T backend pytest
```
