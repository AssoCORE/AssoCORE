## What Are Secrets?

**Secrets** are sensitive pieces of information that your application needs to function but should never be shared publicly:

- 🔑 **Passwords** - Database, admin accounts, API keys
- 🔐 **API Keys** - Third-party service credentials
- 🎫 **Tokens** - Authentication tokens, session secrets
- 📜 **Certificates** - SSL/TLS certificates and private keys
- 🔗 **Connection Strings** - Database URLs with embedded credentials

**Why secrets matter:**
- Exposed secrets = Security breach
- Anyone with your secrets can access/control your systems
- Once leaked online, secrets must be considered compromised forever

## The .env File

### What Is a .env File?

A `.env` (dot-env) file is a simple text file that stores environment variables:

```bash title="k8s/.env"
# This is a comment
VARIABLE_NAME=value
ANOTHER_VARIABLE=another-value
SECRET_PASSWORD=super-secret-123
```

**Key principles:**
- One variable per line
- Format: `KEY=value` (no spaces around `=`)
- Comments start with `#`
- No quotes needed for values (usually)
- **NEVER commit to git!**

### AssoCORE .env Structure

```bash title="k8s/.env"
# =============================================================================
# DATABASE CREDENTIALS (MariaDB)
# =============================================================================

# MariaDB root password (for administrative tasks)
MARIADB_ROOT_PASSWORD=your-secure-password-here

# Database name
MARIADB_DATABASE=assocore

# Database user for application access
MARIADB_USER=assocore

# Database user password
MARIADB_PASSWORD=another-secure-password

# =============================================================================
# NEXTCLOUD CREDENTIALS
# =============================================================================

# NextCloud admin username
NEXTCLOUD_ADMIN_USER=admin

# NextCloud admin password
NEXTCLOUD_ADMIN_PASSWORD=yet-another-secure-password

# =============================================================================
# GRAFANA CREDENTIALS
# =============================================================================

# Grafana admin username
GRAFANA_ADMIN_USER=admin

# Grafana admin password
GRAFANA_ADMIN_PASSWORD=grafana-secure-password

# =============================================================================
# TRAEFIK DASHBOARD CREDENTIALS
# =============================================================================

# Traefik dashboard username
TRAEFIK_DASHBOARD_USER=admin

# Traefik dashboard password
TRAEFIK_DASHBOARD_PASSWORD=traefik-secure-password
```

## Step-by-Step Tutorial

### Tutorial 1: First Time Setup

<Steps>

1. **Navigate to your project**

   ```bash
   cd /path/to/AssoCORE
   ```

2. **Check if .env exists**

   ```bash
   ls -la k8s/.env
   ```
   
   If it exists, you're already set up! If not, continue...

3. **Copy the example template**

   ```bash
   cp k8s/.env.example k8s/.env
   ```

4. **Open the file**

   ```bash
   # Using nano (beginner-friendly)
   nano k8s/.env
   
   # Using vim (advanced)
   vim k8s/.env
   
   # Using VS Code
   code k8s/.env
   ```

5. **Generate your first password**

   In a separate terminal:
   
   ```bash
   openssl rand -base64 32
   ```
   
   Copy the output: `rJ8K2mP9vL3nQ5tW7xY1zB4cD6fG8hJ0`

6. **Paste into .env file**

   Find this line:
   ```bash
   MARIADB_ROOT_PASSWORD=
   ```
   
   Replace with your generated password:
   ```bash
   MARIADB_ROOT_PASSWORD=rJ8K2mP9vL3nQ5tW7xY1zB4cD6fG8hJ0
   ```

7. **Repeat for all passwords**

   Generate and fill in:
   - `MARIADB_PASSWORD`
   - `NEXTCLOUD_ADMIN_PASSWORD`

8. **Save and close**

   - Nano: `Ctrl+O`, `Enter`, `Ctrl+X`
   - Vim: `:wq`
   - VS Code: `Ctrl+S`, close tab

9. **Verify it's not tracked by git**

   ```bash
   git status
   ```
   
   You should **NOT** see `k8s/.env` in the output.

10. **Test your configuration**

    ```bash
    # Load the .env file
    set -a
    source k8s/.env
    set +a
    
    # Check if variables are loaded
    echo "Database: $MARIADB_DATABASE"
    echo "User: $MARIADB_USER"
    # Don't echo passwords!
    ```

</Steps>

### Tutorial 2: Deploy with Secrets

<Steps>

1. **Ensure .env is configured**

   ```bash
   # Check file exists and has content
   cat k8s/.env | grep MARIADB_ROOT_PASSWORD
   ```
   
   Should show: `MARIADB_ROOT_PASSWORD=your-password-here`

2. **Create Kubernetes secrets**

   ```bash
   ./k8s/01-secrets/create-app-secrets.sh
   ```
   
   This reads your `.env` file and creates Kubernetes secrets.

3. **Verify secrets were created**

   ```bash
   kubectl get secrets -n assocore
   ```
   
   You should see:
   - `mariadb-secret`
   - `backend-db-secret`
   - `nextcloud-secret`

4. **Deploy your applications**

   ```bash
   ./k8s/deploy-apps.sh
   ```
   
   The script will use the secrets automatically.

5. **Access your application**

   - Frontend: http://assocore.localhost
   - NextCloud: http://files.assocore.localhost
   
   Login with the credentials from your `.env` file!

</Steps>

### Tutorial 3: Update Passwords

<Steps>

1. **Generate new passwords**

   ```bash
   openssl rand -base64 32
   openssl rand -base64 32
   openssl rand -base64 32
   ```

2. **Edit .env file**

   ```bash
   nano k8s/.env
   ```
   
   Replace old passwords with new ones.

3. **Update Kubernetes secrets**

   ```bash
   ./k8s/01-secrets/create-app-secrets.sh
   ```

4. **Restart services**

   ```bash
   # Restart all affected services
   kubectl rollout restart statefulset/mariadb -n assocore
   kubectl rollout restart deployment/backend -n assocore
   kubectl rollout restart statefulset/nextcloud -n assocore
   ```

5. **Wait for services to restart**

   ```bash
   kubectl get pods -n assocore -w
   ```
   
   Wait until all pods show `Running` status.

6. **Test new credentials**

   Login to NextCloud with your new password!

</Steps>

## Password Generation

### Using OpenSSL (Recommended)

```bash
# Generate a 32-character password
openssl rand -base64 32

# Output example:
# rJ8K2mP9vL3nQ5tW7xY1zB4cD6fG8hJ0kL2mN4o=
```

### Using pwgen

```bash
# Install pwgen
sudo apt install pwgen  # Ubuntu/Debian
brew install pwgen      # Mac

# Generate passwords
pwgen -s 32 1  # Secure, 32 chars, 1 password
pwgen -s 32 5  # Generate 5 passwords at once
```

### Using Python

```bash
python3 -c "import secrets, string; print(''.join(secrets.choice(string.ascii_letters + string.digits) for _ in range(32)))"
```

### Password Requirements

<CardGrid>
  <Card title="Length" icon="ruler">
    **Minimum: 24 characters**
    
    Longer = More secure
    
    Recommended: 32-40 characters
  </Card>

  <Card title="Complexity" icon="puzzle">
    **Mix character types:**
    - Uppercase letters (A-Z)
    - Lowercase letters (a-z)
    - Numbers (0-9)
    - Special characters (!@#$%)
  </Card>

  <Card title="Uniqueness" icon="star">
    **Never reuse passwords!**
    
    Each service gets its own unique password
    
    Database ≠ NextCloud ≠ Backend
  </Card>

  <Card title="Randomness" icon="random">
    **Use crypto-grade generators**
    
    ✅ OpenSSL, pwgen, secrets module
    
    ❌ Dictionary words, patterns, personal info
  </Card>
</CardGrid>

## Security Best Practices

### ✅ DO

<CardGrid>
  <Card title="Use Strong Passwords" icon="approve-check">
    - Minimum 24 characters
    - Crypto-random generation
    - Unique per service
  </Card>

  <Card title="Keep Secrets Secret" icon="warning">
    - Never commit to git
    - Don't share via email/chat
    - Use password managers
  </Card>

  <Card title="Rotate Regularly" icon="refresh">
    - Every 90 days minimum
    - After team member leaves
    - If compromise suspected
  </Card>

  <Card title="Use Secret Managers" icon="seti:lock">
    - HashiCorp Vault
    - AWS Secrets Manager
    - Azure Key Vault
    - GCP Secret Manager
  </Card>
</CardGrid>

### ❌ DON'T

<Aside type="danger" title="Never Do These!">

- ❌ Commit `.env` files to git
- ❌ Use simple passwords like "password123"
- ❌ Reuse passwords across services
- ❌ Share passwords in Slack/email
- ❌ Store passwords in plain text notes
- ❌ Use default/example passwords in production
- ❌ Include secrets in Docker images
- ❌ Log passwords in application logs

</Aside>

## Troubleshooting

### Issue: "Missing .env file"

```bash
Error: .env file not found at k8s/.env
```

**Solution:**

```bash
# Copy the example
cp k8s/.env.example k8s/.env

# Edit and fill in values
nano k8s/.env
```

### Issue: "Missing required environment variables"

```bash
Error: Missing required environment variables:
  - MARIADB_ROOT_PASSWORD
  - MARIADB_PASSWORD
```

**Solution:**

Open `k8s/.env` and ensure every variable has a value (no empty lines like `MARIADB_ROOT_PASSWORD=`)

### Issue: "Permission denied"

```bash
bash: k8s/.env: Permission denied
```

**Solution:**

```bash
# Fix file permissions
chmod 600 k8s/.env

# Verify
ls -la k8s/.env
# Should show: -rw------- (readable/writable by owner only)
```

### Issue: "Secrets already exist"

```bash
Error from server (AlreadyExists): secrets "mariadb-secret" already exists
```

**Solution:**

The script automatically handles this with `--dry-run=client -o yaml | kubectl apply -f -`, but if you still see errors:

```bash
# Delete old secrets
kubectl delete secret mariadb-secret backend-db-secret nextcloud-secret -n assocore

# Recreate
./k8s/01-secrets/create-app-secrets.sh
```

### Issue: ".env file shows in git status"

```bash
$ git status
modified: k8s/.env
```

**Solution:**

```bash
# Ensure .gitignore has the entry
grep "k8s/.env" .gitignore

# If missing, add it
echo "k8s/.env" >> .gitignore

# Remove from git if already tracked
git rm --cached k8s/.env
git commit -m "Remove .env from git tracking"
```

## Advanced Topics

### Using Environment-Specific Files

```bash
# Create multiple .env files
k8s/.env.dev
k8s/.env.staging
k8s/.env.prod

# Load specific environment
cp k8s/.env.dev k8s/.env
./k8s/deploy-apps.sh
```

### Integrating with CI/CD

```yaml title=".github/workflows/deploy.yml"
name: Deploy to Kubernetes

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Create .env from secrets
        run: |
          cat > k8s/.env << EOF
          MARIADB_ROOT_PASSWORD=${{ secrets.DB_ROOT_PASSWORD }}
          MARIADB_DATABASE=assocore
          MARIADB_USER=assocore
          MARIADB_PASSWORD=${{ secrets.DB_PASSWORD }}
          NEXTCLOUD_ADMIN_USER=admin
          NEXTCLOUD_ADMIN_PASSWORD=${{ secrets.NEXTCLOUD_PASSWORD }}
          EOF
      
      - name: Deploy
        run: |
          ./k8s/01-secrets/create-app-secrets.sh
          ./k8s/deploy-apps.sh
```

### Using HashiCorp Vault

```bash
# Store secrets in Vault
vault kv put secret/assocore/db \
  root_password="$(openssl rand -base64 32)" \
  user_password="$(openssl rand -base64 32)"

# Fetch and create .env
vault kv get -format=json secret/assocore/db | \
  jq -r '.data.data | to_entries | .[] | "\(.key | ascii_upcase)=\(.value)"' > k8s/.env
```

### Encrypting .env Files

If you must store `.env` files, encrypt them:

```bash
# Encrypt
gpg --symmetric --cipher-algo AES256 k8s/.env

# Creates: k8s/.env.gpg (safe to commit)

# Decrypt
gpg --decrypt k8s/.env.gpg > k8s/.env
```

## Quick Reference

### Essential Commands

```bash
# Generate password
openssl rand -base64 32

# Create .env from example
cp k8s/.env.example k8s/.env

# Load .env into shell
set -a; source k8s/.env; set +a

# Create Kubernetes secrets
./k8s/01-secrets/create-app-secrets.sh

# View secret value
kubectl get secret mariadb-secret -n assocore \
  -o jsonpath='{.data.password}' | base64 -d

# Update secrets
nano k8s/.env
./k8s/01-secrets/create-app-secrets.sh
kubectl rollout restart deployment/backend -n assocore
```

### File Locations

```text
k8s/.env.example          # Template (committed to git)
k8s/.env                  # Your secrets (NOT committed)
k8s/01-secrets/create-app-secrets.sh  # Secret creation script
```

### Security Checklist

- [ ] `.env` file created from example
- [ ] All passwords are 24+ characters
- [ ] Passwords generated with crypto-random tool
- [ ] Each service has unique password
- [ ] `.env` file has `600` permissions (rw-------)
- [ ] `.env` not in git (verify with `git status`)
- [ ] Passwords stored in password manager
- [ ] Team knows NOT to commit secrets
