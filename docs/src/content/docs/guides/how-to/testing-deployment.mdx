Complete verification guide for testing your AssoCORE Kubernetes deployment from start to finish.

## Overview

This guide covers testing:
- ✅ Secret management configuration
- ✅ Kubernetes cluster health
- ✅ Core services (Traefik, Prometheus, Grafana)
- ✅ Application stack (Backend, Frontend, Database, Nextcloud)
- ✅ Networking and ingress
- ✅ Observability and monitoring

<Aside type="tip" title="Fresh Start">
This guide assumes you're starting from a clean cluster. If you have existing deployments, [clean up first](#cleanup-before-testing).
</Aside>

## Prerequisites

<Steps>

1. **Verify Tools Installation**

   ```bash
   # Check kubectl
   kubectl version --client

   # Check Docker
   docker --version

   # Check k3d (if using k3d)
   k3d version
   ```

2. **Clone Repository**

   ```bash
   git clone https://github.com/AssoCORE/AssoCORE.git
   cd AssoCORE
   ```

3. **Verify File Structure**

   ```bash
   # Check k8s directory exists
   ls -la k8s/

   # Verify core directories
   ls k8s/0*/ k8s/01-secrets/ k8s/02-traefik/
   ```

</Steps>

## Phase 1: Secrets Configuration

### Step 1: Create .env File

<Steps>

1. **Copy template**

   ```bash
   cp k8s/.env.example k8s/.env
   ```

2. **Generate secure passwords**

   ```bash
   # Generate passwords
   echo "MARIADB_ROOT_PASSWORD=$(openssl rand -base64 32)"
   echo "MARIADB_PASSWORD=$(openssl rand -base64 32)"
   echo "NEXTCLOUD_ADMIN_PASSWORD=$(openssl rand -base64 32)"
   echo "GRAFANA_ADMIN_PASSWORD=$(openssl rand -base64 32)"
   ```

3. **Edit .env file**

   ```bash
   nano k8s/.env
   ```

   Set these required values:
   ```bash
   MARIADB_ROOT_PASSWORD=<generated-password-1>
   MARIADB_DATABASE=assocore
   MARIADB_USER=assocore
   MARIADB_PASSWORD=<generated-password-2>

   NEXTCLOUD_ADMIN_USER=admin
   NEXTCLOUD_ADMIN_PASSWORD=<generated-password-3>

   GRAFANA_ADMIN_USER=admin
   GRAFANA_ADMIN_PASSWORD=<generated-password-4>
   ```

4. **Verify .env is ignored by git**

   ```bash
   git status
   # Should NOT show k8s/.env

   # Check gitignore
   grep -r "\.env" .gitignore
   # Should show .env patterns
   ```

</Steps>

### Step 2: Test Secret Generation

<Aside type="note">
Don't create secrets yet - we'll do this after the cluster is ready.
</Aside>

```bash
# Verify the script exists
ls -la k8s/01-secrets/create-app-secrets.sh

# Make it executable if needed
chmod +x k8s/01-secrets/create-app-secrets.sh

# Verify GHCR script
ls -la k8s/01-secrets/create-ghcr-secret.sh
chmod +x k8s/01-secrets/create-ghcr-secret.sh
```

**✅ Phase 1 Complete**: Secrets configuration ready

## Phase 3: Core Services Deployment

<Aside type="caution" title="Critical: Order Matters!">
**You MUST create secrets BEFORE deploying core services.** Traefik and other services depend on secrets existing at startup. If you deploy services before creating secrets, you'll see middleware and authentication errors.

**Correct order:**
1. Create `.env` file
2. Run `create-app-secrets.sh`
3. Verify secrets exist
4. Deploy core services
</Aside>

### Step 1: Create Secrets

```bash
# Create namespace first
kubectl apply -f k8s/00-namespace/namespace.yaml

# Verify namespace
kubectl get namespace assocore
```


## Phase 4: Core Services Verification

### Test 1: Traefik Ingress Controller

```bash
kubectl logs -n assocore deployment/traefik --tail=50
```

**Expected:** No errors, service has EXTERNAL-IP (or LoadBalancer pending)

```bash
# Port-forward to Prometheus
kubectl port-forward -n assocore svc/prometheus 9090:9090
```

Open browser: **http://localhost:9090**

**Verify:**
- ✅ Prometheus UI loads
- ✅ Status > Targets shows endpoints
- ✅ Query `up` returns results

### Test 3: Grafana Dashboards

```bash
# Port-forward to Grafana
kubectl port-forward -n assocore svc/grafana 3000:3000
```

Open browser: **http://localhost:3000**

**Login with:**
- Username: `admin` (or from your `GRAFANA_ADMIN_USER`)
- Password: From your `k8s/.env` (`GRAFANA_ADMIN_PASSWORD`)

**Verify:**
- ✅ Grafana UI loads
- ✅ Login successful
- ✅ Prometheus datasource connected (Configuration > Data Sources)
- ✅ Dashboards exist (Dashboards > Browse)

### Test 4: Watchtower Auto-Updater

```bash
# Check Watchtower logs
kubectl logs -n assocore deployment/watchtower --tail=50
```

**Expected:** Logs showing container monitoring activity

## Phase 5: Application Stack Deployment

### Step 1: Deploy Database

```bash

kubectl apply -f k8s/08-redis/redis-deployment.yaml

kubectl wait --for=condition=available deployment/redis -n assocore --timeout=180s
```

```bash

kubectl apply -f k8s/10-frontend/frontend-deployment.yaml
```

## Troubleshooting

### Pod Not Starting

```bash
# Check pod status
kubectl describe pod <pod-name> -n assocore

# Check logs
kubectl logs <pod-name> -n assocore

# Common issues:
# - ImagePullBackOff: Check GHCR secret
# - CrashLoopBackOff: Check logs for errors
# - Pending: Check resource requests
```

### Secret Not Found Errors

```bash
# Recreate secret
./k8s/01-secrets/create-app-secrets.sh

# Verify secret exists
kubectl get secret <secret-name> -n assocore -o yaml

# Restart pod to pick up secret
kubectl rollout restart deployment/<deployment-name> -n assocore
```

### Grafana Login Issues

```bash
# Check Grafana logs
kubectl logs -n assocore deployment/grafana

# Verify secret
kubectl get secret grafana-admin -n assocore -o jsonpath='{.data.admin-user}' | base64 -d
kubectl get secret grafana-admin -n assocore -o jsonpath='{.data.admin-password}' | base64 -d

# Restart Grafana
kubectl rollout restart deployment/grafana -n assocore
```

### Database Connection Errors

```bash
# Check MariaDB logs
kubectl logs mariadb-0 -n assocore

# Test connection
kubectl exec -it mariadb-0 -n assocore -- mysql -u assocore -p

# Verify secret
kubectl get secret mariadb-secret -n assocore -o yaml
```

### Port Forward Issues

```bash
# Kill all port forwards
pkill -f "kubectl port-forward"

# Restart specific port-forward
kubectl port-forward -n assocore svc/<service-name> <local-port>:<service-port>
```

### Traefik Middleware Not Found

**Error:**
```
middleware "assocore-traefik-dashboard-auth@kubernetescrd" does not exist
```

**Cause**: The Traefik dashboard auth secret wasn't created before deploying Traefik.

**Fix:**
```bash
# Create the missing secret
./k8s/01-secrets/create-app-secrets.sh

# Verify it exists
kubectl get secret traefik-dashboard-auth-secret -n assocore

# Restart Traefik
kubectl rollout restart deployment/traefik -n assocore
```

### Let's Encrypt Certificate Errors

**Error Type 1 - DNS Not Configured:**
```
DNS problem: NXDOMAIN looking up A for traefik.assocore.org
```

**Cause**: Domain doesn't have DNS records yet.

**Fix**: Either configure DNS or use HTTP for local testing (see below).

**Error Type 2 - Invalid Local Domains:**
```
Cannot issue for "prometheus.assocore.local": Domain name does not end with a valid public suffix (TLD)
```

**Cause**: Let's Encrypt **cannot** issue certificates for:
- `.local` domains
- `localhost` domains  
- Any non-public domain

**Fix for Local Development:**

<Aside type="tip">
Use HTTP instead of HTTPS for local development to avoid Let's Encrypt errors.
</Aside>

```bash
# Apply development ingress routes (HTTP only)
kubectl apply -f k8s/06-ingress/observability-ingress-dev.yaml
kubectl apply -f k8s/02-traefik/traefik-dashboard-dev.yaml

# Access via HTTP
curl http://prometheus.localhost  # or http://grafana.localhost
curl http://traefik.localhost/dashboard/
```

**Fix for Production:**

1. **Set up DNS records** pointing to your cluster's external IP
2. **Change domains** in ingress files to your real domains
3. **Update email** in `k8s/02-traefik/traefik-config.yaml`
4. **Use staging first** to test:
   ```yaml
   # In traefik-config.yaml
   caServer: https://acme-staging-v02.api.letsencrypt.org/directory
   ```
5. **Then switch to production** Let's Encrypt

## Cleanup Before Testing

If you need to start fresh:

```bash
# Delete everything in namespace
kubectl delete namespace assocore

# Or delete specific resources
kubectl delete all --all -n assocore
kubectl delete pvc --all -n assocore
kubectl delete secrets --all -n assocore

# Delete cluster (k3d only)
k3d cluster delete assocore
```
