AssoCORE's backend is built with FastAPI, using async Python, SQLAlchemy 2.0, and MariaDB.

The backend image is built from `docker/backend.Dockerfile` (multi-stage, `development` and `production` targets) and orchestrated by the single `docker-compose.yml` at the repository root.

## Route Auto-Discovery

`routes/__init__.py` uses `pkgutil.iter_modules` to discover every module in the `routes` package and register any `APIRouter` it exports as `router`. Routers mount at the app root (`/user/...`, `/event/...`) — there is **no** `/api` prefix.

**To add a new route file:** create `app/routes/myfeature.py` with `router = APIRouter(...)` — no other wiring needed.

## Authentication

<Tabs>
  <TabItem label="Flow">
    1. `POST /user/login` → `{ access_token, refresh_token, expires_in }`. Access token lasts 15 min; refresh token 30 days.
    2. Client includes `Authorization: Bearer <access_token>` on protected requests.
    3. `get_current_user` dependency validates the token, checks the redis blacklist, and returns the `User` ORM object — or raises 401.
    4. `POST /user/refresh` rotates the refresh token. Replaying an already-used token outside a 10 s grace window is treated as theft: the whole family is revoked.
    5. `POST /user/logout` blacklists the access token and (if given) kills its refresh family.
    6. `POST /user/logout/all` kills every refresh family for the user.

    ```python
    from app.core.dependencies import get_current_user

    @router.get("/protected")
    async def protected(current_user: User = Depends(get_current_user)):
        return {"id": current_user.id}
    ```
  </TabItem>

  <TabItem label="RBAC">
    ```python
    from app.core.dependencies import require_admin, require_roles

    # Admin only
    @router.delete("/{id}", dependencies=[Depends(require_admin)])
    async def delete_something(id: int, ...): ...

    # Admin or staff
    @router.post("/", dependencies=[Depends(require_roles("admin", "staff"))])
    async def create_something(...): ...
    ```

    Put the gate in `APIRouter(dependencies=[...])` so new routes in a file cannot forget it.
  </TabItem>

  <TabItem label="Redis">
    Token revocation state lives in Redis (DB 1, separate from Nextcloud's cache on DB 0). `TokenStore` in `core/tokens.py` manages:

    - Access token blacklist (key TTL = token remaining life)
    - Refresh token rotation with Lua atomic consume
    - Per-user family set for `logout/all`
    - Password-reset tokens (SHA-256 hash → user_id, single-use GETDEL)

    If Redis is down: revocation checks are skipped (`AUTH_REDIS_STRICT=false`), but refresh and logout return 503 — they cannot be honoured without Redis.
  </TabItem>
</Tabs>

## Password Reset

<Tabs>
  <TabItem label="Flow">
    1. `POST /user/password/forgot` — always returns 202 (no enumeration oracle). Generates a `secrets.token_urlsafe(32)` token, stores its SHA-256 hash in Redis with a `PASSWORD_RESET_EXPIRE_MINUTES` TTL, sends a reset link via `send_mail()`.
    2. `POST /user/password/reset` — consumes the token (single-use GETDEL), validates the new password, commits, **kills all active sessions** (`kill_user_sessions`), notifies the user.

    The session-kill step is the security point: someone resetting a compromised password must not leave the attacker's refresh tokens alive.
  </TabItem>
  <TabItem label="Security properties">
    - Token stored as SHA-256 hash — a Redis dump never grants a reset.
    - Single use — GETDEL is atomic; a second call with the same token returns 400.
    - Rate-limited — `5/min` on the forgot endpoint, same as login.
    - Enumeration-safe — 202 regardless of whether the address exists.
    - SMTP failure logged at ERROR and returns 202 — the caller cannot distinguish an SMTP outage from an unknown address.
  </TabItem>
</Tabs>

## Mail

`core/mail.py` exposes a single `async def send_mail(to, subject, body, html=None) -> bool` function backed by `aiosmtplib`.

Key behaviour:
- `MAIL_ENABLED=false` (default): logs at INFO and returns `False` without connecting. Safe on a dev box with no SMTP.
- Transport failures: logs at ERROR, returns `False`. **Never raises.** Bulk/courtesy email cannot 500 a request that already succeeded.
- In dev, Mailpit (`:1025` SMTP, `:8025` web UI) catches all mail with nothing leaving the machine.

See the [Environment Variables](#environment-variables) section for all `MAIL_*` / `SMTP_*` config keys.

## Database

<Tabs>
  <TabItem label="Setup">
    `db/database.py` creates the async SQLAlchemy engine from `DATABASE_URL` (or the individual `MYSQL_*` env vars). `init_db()` runs on app startup:

    1. Creates the app database and user if missing
    2. Calls `Base.metadata.create_all` — tables are created from models

    <Aside type="caution">
      There is no Alembic migration system. `create_all` only creates **missing tables** — it never adds a column to an existing one. Adding a field to a live model is a silent no-op against an existing database. Model new data as a new table, or introduce Alembic.
    </Aside>
  </TabItem>

  <TabItem label="Session injection">
    ```python
    from app.db.database import get_session

    @router.get("/items")
    async def list_items(session: AsyncSession = Depends(get_session)):
        result = await session.execute(select(Item))
        return result.scalars().all()
    ```
  </TabItem>

  <TabItem label="Eager loading">
    Async SQLAlchemy does not support lazy loading — accessing an unloaded relationship raises `MissingGreenlet`. Always use `selectinload` or `joinedload`:

    ```python
    from sqlalchemy.orm import selectinload

    result = await session.execute(
        select(User)
        .options(selectinload(User.roles), selectinload(User.notifications))
        .where(User.id == user_id)
    )
    user = result.scalar_one_or_none()
    ```

    The `_user_q()` helper in `routes/user.py` is the established pattern. Relationships read on every request (e.g. `User.nc_account`) declare `lazy="selectin"` on the model instead.
  </TabItem>
</Tabs>

## Data Models

```
User ──< user_roles >── Role
User ──< Notification
User ──< Reminder
User ──< Event (creator_id)

User ──< event_staff >── Event
```

All foreign keys use `ondelete="CASCADE"` so deleting a user removes their notifications, reminders, and event memberships.

## Schemas

`schemas/classes.py` defines Pydantic models with `from_attributes=True` for all I/O:

| Schema | Purpose |
|--------|---------|
| `LoginRequest` | `POST /user/login` body |
| `Token` | Login / refresh response |
| `RefreshRequest` | `POST /user/refresh` body |
| `LogoutRequest` | `POST /user/logout` body (refresh_token optional) |
| `UserCreate` | Registration body |
| `UserUpdate` | Partial profile update |
| `UserOut` | Response — no password, includes roles/notifications/reminders |
| `NotificationOut` / `NotificationCreate` | Notification I/O |
| `ReminderCreate` / `ReminderOut` | Reminder I/O |
| `EventCreate` / `EventUpdate` / `EventOut` | Event I/O |
| `ForgotPasswordRequest` | `{ mail: EmailStr }` |
| `ResetPasswordRequest` | `{ token: str, password: PasswordStr }` |
| `Page[T]` | Generic paginated response `{ items, total, limit, offset }` |

<Aside type="note">
  `PasswordStr` enforces: 8–50 chars, at least one uppercase, one lowercase, one digit, and one of `#?!@$%^&*-`. `front/lib/auth/schemas.ts` mirrors this regex exactly so client-side validation matches server 422s.
</Aside>

## Security

<CardGrid>
  <Card title="JWT — HS256" icon="rocket">
    15 min access tokens + 30 day refresh tokens. Refresh rotation with reuse detection — replaying a consumed token kills the whole family. `SECRET_KEY` must be changed before any deployment.
  </Card>

  <Card title="bcrypt" icon="star">
    Passwords hashed with bcrypt before storage. `verify_password` uses constant-time comparison.
  </Card>

  <Card title="RBAC" icon="puzzle">
    Three roles: `admin`, `staff`, `member`. `require_roles` / `require_admin` FastAPI dependencies gate routes. Put the gate in `APIRouter(dependencies=[...])` so new routes cannot forget it.
  </Card>

  <Card title="Rate limiting" icon="approve-check">
    `slowapi` limits login and password-forgot to 5 req/min per IP. `limiter.enabled = False` in tests.
  </Card>
</CardGrid>

## Notifications Contract

Nothing writes to `notifications` except `core/notifications.py`. Always call `notify()` / `notify_role()` **after** committing the triggering work — they manage their own commit/rollback and swallow every `Exception`, so a failed notification never turns a successful action into a 500.

`POST /user/notification/` is the exception: creating a notification is the caller's whole intent there, so it raises normally.

## Pagination

All list endpoints return `Page[T]` — `{ items, total, limit, offset }`. `total` is the count before `limit`/`offset` so clients can render page counts. Use `paginate()` with `limit_param()` / `offset_param()` from `app.core.pagination`, and filter in SQL rather than post-filtering in Python.
