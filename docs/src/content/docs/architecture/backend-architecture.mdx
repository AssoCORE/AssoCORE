AssoCORE's backend is built with FastAPI, using async Python, SQLAlchemy, and MariaDB.

## Project Structure

```

│   │
```

## Route Auto-Discovery

`routes/__init__.py` uses `pkgutil.iter_modules` to discover every module in the `routes` package and register any `APIRouter` it finds as `router`. All routers are aggregated under the `/api` prefix.

**To add a new route file:** create `app/routes/myfeature.py` with `router = APIRouter(...)` — no other wiring needed.

## Authentication

<Tabs>
  <TabItem label="Flow">
    1. Client sends `POST /api/user/login` with `{ username, password }` JSON
    2. Backend verifies bcrypt hash; returns `{ access_token, token_type: "bearer" }`
    3. Client includes `Authorization: Bearer <token>` on subsequent requests
    4. `get_current_user` dependency decodes the JWT, resolves the user ID, and returns the `User` ORM object — or raises 401

    ```python
    from app.core.dependencies import get_current_user

    @router.get("/protected")
    async def protected(current_user: User = Depends(get_current_user)):
        return {"id": current_user.id}
    ```
  </TabItem>

  <TabItem label="core/security.py">
    ```python
    # Tokens are HS256, 24 h expiry, sub = str(user_id)
    def hash_password(password: str) -> str: ...
    def verify_password(plain: str, hashed: str) -> bool: ...
    def create_access_token(user_id: int) -> str: ...
    def decode_token(token: str) -> int: ...
    ```

    `SECRET_KEY` is read from the `SECRET_KEY` environment variable. The default in `.env` is a placeholder — **change it before any deployment**.
  </TabItem>

  <TabItem label="core/dependencies.py">
    ```python
    bearer = HTTPBearer()

    async def get_current_user(
        credentials: HTTPAuthorizationCredentials = Depends(bearer),
        session: AsyncSession = Depends(get_session),
    ) -> User:
        user_id = decode_token(credentials.credentials)  # raises 401 on bad/expired token
        user = await session.get(User, user_id)
        if not user:
            raise HTTPException(401)
        return user
    ```
  </TabItem>
</Tabs>

## Database

<Tabs>
  <TabItem label="Setup">
    `db/database.py` creates the async SQLAlchemy engine from `DATABASE_URL` (or the individual `MYSQL_*` env vars). `init_db()` runs on app startup via the FastAPI lifespan:

    1. Connects as root and creates the app database + user if missing
    2. Calls `Base.metadata.create_all` — tables are created from models, no migration tool

    <Aside type="caution">
      There is no Alembic migration system. Schema changes require manual `ALTER TABLE` or a full DB reset in dev.
    </Aside>
  </TabItem>

  <TabItem label="Session injection">
    ```python
    from app.db.database import get_session

    @router.get("/items")
    async def list_items(session: AsyncSession = Depends(get_session)):
        result = await session.execute(select(Item))
        return result.scalars().all()
    ```
  </TabItem>

  <TabItem label="Eager loading">
    Async SQLAlchemy does not support lazy loading — accessing an unloaded relationship raises `MissingGreenlet`. Always use `selectinload` or `joinedload`:

    ```python
    from sqlalchemy.orm import selectinload

    result = await session.execute(
        select(User)
        .options(selectinload(User.roles), selectinload(User.notifications))
        .where(User.id == user_id)
    )
    user = result.scalar_one_or_none()
    ```

    The `_user_q()` helper in `routes/user.py` is the established pattern for loading a user with all relationships.
  </TabItem>
</Tabs>

## Data Models

```
User ──< user_roles >── Role
User ──< Notification
User ──< Reminder
User ──< Event (creator)
User ──< event_registrations >── Event
User ──< event_staff >── Event
```

All foreign keys use `ondelete="CASCADE` so deleting a user removes their notifications, reminders, and events.

## Schemas

`schemas/classes.py` defines Pydantic models with `from_attributes=True` (ORM mode) for all I/O:

| Schema | Purpose |
|--------|---------|
| `LoginRequest` | `POST /user/login` body |
| `Token` | Login response |
| `UserCreate` | Registration body (password validated by regex) |
| `UserUpdate` | Partial update (all fields optional) |
| `UserOut` | Response — no password field, includes roles/notifications/reminders |
| `RoleOut` | Embedded in `UserOut` |
| `NotificationOut` | Notification response |
| `ReminderCreate` | Reminder creation body |
| `ReminderOut` | Reminder response |
| `EventCreate` / `EventOut` | Event I/O (routes not yet wired) |

<Aside type="note">
  `PasswordStr` is a custom annotated type enforcing min 8 chars, uppercase, lowercase, digit, and special character.
</Aside>

## Security

<CardGrid>
  <Card title="JWT — HS256" icon="rocket">
    Tokens signed with `SECRET_KEY`, 24 h expiry, subject = user ID. Decoded and verified on every protected request by `get_current_user`.
  </Card>

  <Card title="bcrypt" icon="star">
    Passwords hashed with bcrypt before storage. `verify_password` uses constant-time comparison.
  </Card>

  <Card title="CORS" icon="puzzle">
    Restricted to `http://localhost:3000` and `http://127.0.0.1:3000` in development. Update `allow_origins` in `main.py` for production.
  </Card>

  <Card title="Input validation" icon="approve-check">
    All request bodies validated by Pydantic schemas. Email format, phone E.164 pattern, and password complexity are enforced at the schema level.
  </Card>
</CardGrid>

<Aside type="caution" title="RBAC not yet enforced">
  The `Role` model and `user_roles` M2M table exist, but role checks are not implemented in any route handler yet. All authenticated users currently have the same level of access.
</Aside>
