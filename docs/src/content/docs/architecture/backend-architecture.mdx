## Architectural Layers

<Tabs>
  <TabItem label="API Layer" icon="seti:html">
    FastAPI routers and endpoints handling HTTP requests.

    **Responsibilities:**

    - Request/response handling
    - Input validation (via Pydantic)
    - HTTP status codes
    - API documentation

      The API layer should remain thin, delegating business logic to services.

  <TabItem label="Service Layer" icon="seti:python">
    Business logic and application workflows.

    **Responsibilities:**

    - Business rules enforcement
    - Complex operations coordination
    - Service-to-service communication
    - Transaction management

    <Aside type="tip">
      Services orchestrate repositories and contain the core business logic.
    </Aside>
  </TabItem>

  <TabItem label="Repository Layer" icon="seti:db">
    Data access abstraction.

    **Responsibilities:**

    - Database queries
    - CRUD operations
    - Data persistence
    - Query optimization

  </TabItem>

    - Output serialization

    - Type safety

## Design Patterns

<Tabs>
  <TabItem label="Dependency Injection">
    FastAPI's dependency injection system provides clean separation of concerns and testability.

    **Use Cases:**
    - Database session management
    - Authentication
    - Service instantiation
    - Configuration access

    ```python
    from fastapi import Depends
    from app.services import UserService

    def get_user_service() -> UserService:
        return UserService()

    @router.get("/users")
    async def list_users(
        service: UserService = Depends(get_user_service)
    ):
        return await service.list_users()
    ```

    <Aside type="tip" title="Testing Benefit">
      Dependencies can be easily mocked in tests, making unit testing straightforward.
    </Aside>
  </TabItem>

  <TabItem label="Repository Pattern">
    Separating data access logic from business logic.

    **Benefits:**
    - Clean separation of concerns
    - Easy to test business logic
    - Database-agnostic service layer
    - Query reusability

    <Aside>
      Repositories abstract away database implementation details from the service layer.
    </Aside>
  </TabItem>

  <TabItem label="Service Pattern">
    Encapsulating business logic in service classes.

    **Benefits:**
    - Centralized business rules
    - Reusable across endpoints
    - Easy to test independently
    - Clear responsibility boundaries
  </TabItem>
</Tabs>

## Key Features

<CardGrid>
  <Card title="Async/Await" icon="rocket">
    Non-blocking I/O for better performance and scalability.

    ```python
    @router.get("/associations")
    async def get_associations():
        async with database.session() as session:
            return await association_service.get_all(session)
    ```
  </Card>

  <Card title="Request Validation" icon="approve-check">
    Automatic validation with Pydantic schemas.

    ```python
    class UserCreate(BaseModel):
        email: EmailStr
        password: constr(min_length=8)
        name: str

    @router.post("/users")
    async def create_user(user: UserCreate):
        # user is already validated
        return await user_service.create(user)
    ```
  </Card>

  <Card title="API Documentation" icon="open-book">
    Auto-generated OpenAPI (Swagger) docs at `/docs` and `/redoc`.

    Documentation is automatically generated from your code, type hints, and docstrings.
  </Card>

  <Card title="Error Handling" icon="warning">
    Centralized exception handling with custom exceptions.

    Consistent error responses across all endpoints with proper HTTP status codes.
  </Card>
</CardGrid>

## Testing Strategy

<Tabs>
  <TabItem label="Unit Tests">
    Testing individual components in isolation.

    **Focus:**
    - Service logic
    - Repository methods
    - Utility functions
    - Business rules

    **Target Coverage:** >80%
  </TabItem>

  <TabItem label="Integration Tests">
    Testing API endpoints with real dependencies.

    **Focus:**
    - API endpoints
    - Database interactions
    - Authentication flows
    - Error responses
  </TabItem>

  <TabItem label="E2E Tests">
    Testing complete user workflows.

    **Focus:**
    - Full user journeys
    - Multi-step processes
    - Real-world scenarios
    - Cross-service interactions
  </TabItem>
</Tabs>

<Aside type="note">
  Test coverage target is >80%, but focus on meaningful tests rather than reaching 100% coverage.
</Aside>
